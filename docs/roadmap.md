# Avenelix Roadmap

This is a directional roadmap, not a commitment to every item.

## Phase 0 — Foundation (current)

- [x] Purchase `avenelix.com`.
- [x] Establish Vercel deployment.
- [x] Move DNS to Cloudflare.
- [x] Build coming-soon landing page.
- [x] Make the page responsive.
- [x] Add SEO metadata.
- [x] Add `robots.txt` and `sitemap.xml`.
- [x] Set up Google Search Console.
- [ ] Complete/verify `hello@avenelix.com` forwarding.
- [ ] Get homepage indexed by Google.

## Phase 1 — Brand + validation

- [ ] Decide the initial positioning from evidence.
- [ ] Identify several real problems worth solving.
- [ ] Talk to potential users/customers.
- [ ] Rank ideas by pain, willingness to pay, feasibility and differentiation.
- [ ] Select one narrow first product/problem.

## Phase 2 — First product

- [ ] Define MVP scope.
- [ ] Define user journey.
- [ ] Define technical architecture.
- [ ] Build a small working prototype.
- [ ] Instrument usage and collect feedback.
- [ ] Validate that users actually want it.

## Phase 3 — Production

Only after validation:

- [ ] Authentication/authorization where required.
- [ ] Billing/subscriptions if applicable.
- [ ] Production observability.
- [ ] Security review.
- [ ] CI/CD.
- [ ] Backups and recovery.
- [ ] Cost/latency controls.
- [ ] Reliability and scaling plan.

## Phase 4 — Public Avenelix website

When there is enough real substance to show, replace the coming-soon page with a full site, potentially containing:

- Home
- What Avenelix does
- Products
- Services
- Work/case studies
- About
- Contact

Do not build all of these merely for appearance before there is content worth showing.

## Phase 5 — Multiple products / studio model

If the first product succeeds, Avenelix can become an umbrella for multiple products and/or services.

Potential structure:

```text
Avenelix
├── Product A
├── Product B
├── Product C
└── Engineering / AI Services
```

The actual structure should be determined by business reality.
